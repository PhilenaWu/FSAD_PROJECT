## Architecture decision: pure functions over raw rows

All analytics live as **pure, exported functions** in `costService.js` that operate on raw
job-level rows shaped exactly like the backend's `inspections` (+ `ai_predictions`) records,
with response shapes matching HLD §6.10. The page calls thin async wrappers.

Why:

- **Swap-to-live is trivial.** When the `/api/admin/costs/*` endpoints land, only the data
  source inside each wrapper changes. The page, shapes, and tests stay identical.
- **Everything is unit-testable** with hand-checkable fixtures — no component rendering, no
  network mocking. 45 Vitest tests cover the engine.
- **Nothing is canned.** Every number on the page is computed at request time from the rows,
  so filters genuinely recompute all KPIs, charts, insights, and flags.

## Forecasting: why damped-trend exponential smoothing

The trend chart projects three months ahead using **Holt's method with a damping factor**
(α = 0.5, β = 0.3, φ = 0.85) rather than a moving average or plain linear regression:

- A moving average ignores trend direction entirely (a rising history "predicts" its own past).
- Undamped linear extrapolation runs away — three months out it will happily predict spend the
  estate has never seen. Damping (φ < 1) flattens the projected trend as the horizon grows,
  which is the textbook guard for short-horizon operational forecasts.
- The fit uses **complete months only** — the current calendar month is excluded because its
  partial total would drag the trend down.

Each projected point carries a **±1.28σ (~80%) range** derived from the model's own
one-step-ahead in-sample errors, widening with √horizon. The model refuses to project with
fewer than three complete months, and clamps at $0.

## Self-validation: walk-forward backtest

The dashboard grades its own model. For each historical month with ≥3 complete months before
it, the model is **refit on strictly earlier data** and its prediction compared against the
real total. The badge next to the trend chart shows the mean absolute percentage error, and
its tooltip lists every prediction vs actual. Properties enforced by test:

- **No peeking** — a spike in month *m* cannot influence the prediction *for* month *m*.
- Zero-spend months are skipped (percentage error against zero is undefined).
- The partial current month is never graded.
- With too little history the badge disappears rather than fake a score; the chip turns
  amber/red honestly if the model is mediocre.

## Honesty guards elsewhere

| Feature | Guard |
| --- | --- |
| Spend movement KPI | Prior window ends the day *before* the current one starts — a job on the boundary date is never double-counted (regression-tested). |
| Top mover (Insights) | Compares the last two **complete** months, so a partial month can't fake a movement. |
| Contractor "Vs peers" benchmark | Compared **within the same category** only (controls job-mix confounding); requires ≥2 own jobs, ≥2 peer jobs, ≥15% deviation before claiming anything. |
| Lift time-to-review | Rate from the last 6 complete months; shows "—" with no recent spend rather than inventing a date. |
| Outlier chips | Only when a job exceeds 2× its category's average, with the average shown in the tooltip. |
| Insights panel | Deterministic rules engine (no LLM): each sentence has a "worth saying" threshold, e.g. contractor concentration only speaks at ≥40% share. |

## Test strategy

`costService.test.js` (Vitest, small fixed fixtures — expected values are hand-checkable):
filter inclusivity · variance windows incl. the boundary case · grouping · trend gap-fill ·
forecast properties (flat→flat with zero-width band, rising→damped rise, partial-month
exclusion, zero clamp, band widening) · backtest no-peeking and edge cases · top-mover rules ·
benchmark evidence guards · insight sentence thresholds · lift watchlist maths.

The audit that produced this suite caught two real bugs: a window-boundary double count in the
variance calculation, and timezone-fragile month arithmetic in the trend gap-fill (replaced
with pure string/int month math).
